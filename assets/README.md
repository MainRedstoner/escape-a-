# assets/ —— 美术素材位（立绘 / 背景 / CG）

这个目录是**预留位**。游戏在运行时按下面的规则去找图：

* **找得到** → 直接用图（自动铺满 1600×900 舞台，背景/CG 按 cover 裁切，立绘按高度缩放、脚底对齐）。
* **找不到** → 在画面上画一张**写清楚规格的占位卡**（虚线框 + 文件名 + 建议尺寸），绝不假装自己有美术。

所以你可以随时把正式美术丢进来，不用改一行代码。加完图之后跑一次：

```bash
python tools/make_manifest.py > assets/manifest.js    # 重新扫描 assets/ → 输出 assets/manifest.js
```

> 为什么清单是 `.js` 而不是 `.json`：本作要求**双击 index.html 就能玩**。`file://` 协议下浏览器会拦掉 `fetch()`，只有 `<script>` 能读本地文件，所以清单写成一个赋值给 `window.EA_ASSETS` 的脚本。

## 一、目录与命名

```
assets/
├── manifest.js          # 自动生成，别手改
├── bg/<id>.jpg|png      # 背景（场景）
├── cg/<id>.jpg|png      # 演出 CG
└── chara/<who>_<face>.png   # 立绘差分（必须 PNG、必须透明底）
```

`<id>` / `<who>` / `<face>` 的取值就是剧本里 `BG()` / `CG()` / `SHOW()` 写的那些 id，由你的剧本决定；立绘的 `who` 需要先在 `src/engine.js` 的 `SPEAKERS` 里注册（见 STORY_GUIDE.md）。

引擎查立绘的顺序：`<who>_<face>.png` → `<who>_normal.png` → 占位卡。所以每个角色至少准备一张 `_normal`。

## 二、尺寸规范

| 类别 | 建议交付尺寸 | 最低要求 | 格式 | 说明 |
| --- | --- | --- | --- | --- |
| 背景 `bg/` | **2560 × 1440** | 1920 × 1080 | jpg/png/webp | 整幅构图。人物立绘会叠在下半部分，所以**画面下方 1/3 别放重要信息** |
| CG `cg/` | **2560 × 1440** | 1920 × 1080 | jpg/png/webp | 整幅演出图。主体建议放在中下偏左或偏右（文本框会盖住底部约 200px） |
| 立绘 `chara/` | **高度 2400**（宽度随人物外轮廓而定，约 900~1700） | 高度 2000 | **PNG-32 透明底** | 全身、正面、脚底贴着画面底边、人物水平居中、左右各留约 2% 余量 |
| 设定表 `sheets/` | 2600 × 1700 | —— | png | 交给画师的基准：三视图 + 表情条 + 实测配色 hex（可选，引擎不读） |

游戏内立绘的显示高度是 **780px**（`scale=1` 时），并排站位在 x=430 / 1170。1600×2400 的图缩下来约 520×780，两个人并排不会打架；多出来的分辨率是给高 DPI 屏幕和以后做特写用的。

## 三、草稿角标

`make_manifest.py` 默认把所有素材标记为 `draft: true`，画面左下角会显示「AI 草稿素材」角标（设置里可关）。换上正式美术后：

```bash
python tools/make_manifest.py --draft 0 > assets/manifest.js
```

角标就不再出现。也可以用 `--final <前缀>` / `--final-kind <类别>` 只把部分素材标记为正式版。

---

## 四、体积提示

背景/CG 建议存为 JPEG（质量 90 上下）控制体积；如果仓库太大，可以转成 WebP（质量 85 左右），`manifest.js` 里的扩展名跟着改就行——`art.js` 认 `jpg / jpeg / png / webp`。
